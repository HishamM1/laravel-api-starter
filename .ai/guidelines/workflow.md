## Workflow

### Commands

- Setup: `composer setup` (installs, creates `.env`, migrates and seeds SQLite). Run locally with `composer dev`.
- Tests: `php artisan test --compact <file or --filter=name>`. Run the narrowest set that covers the change; tests use in-memory SQLite.
- Static analysis: `vendor/bin/phpstan analyse`.
- Format: `vendor/bin/pint <changed files>`.
- CI (`.github/workflows`) runs Pint, Larastan and Pest. Keep all three green.

### API docs

- OpenAPI is generated by `dedoc/scramble` plus `pjadanowski/scramble-extras` (installed from the `HishamM1/scramble-extras` fork, see `repositories` in `composer.json`). The docs are inferred from routes, actions, Data classes and query builder calls. Do not add PHPDoc or attribute annotations to describe requests or responses.
- After changing an endpoint, check the spec with `php artisan scramble:export --path=storage/app/private/api.json` and confirm the request body, query parameters and responses look right.
- If a Data class change does not show up, clear the schema cache with `php artisan scramble-extras:cache:clear`.

### TypeScript types

- Data classes marked `#[TypeScript]` are exported by `php artisan typescript:transform` to `resources/types/api.ts`. Rerun it after changing one, and commit the output.

### Seed data

- `database/seeders/DatabaseSeeder.php` creates `test@example.com` / `password` with the `owner` role. Roles and permissions live in `AdminRoleSeeder`; new admin roles also go into `User::ADMIN_ROLES`.

### Changes

- New env vars go into `.env.example` and the Environment table in `README.md`.
- One logical change per commit, with a short imperative subject.
